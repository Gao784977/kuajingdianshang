## 3a. owner 级工作区分区（S2 移植后新增；S3 验收轮修正表述）

**机制**：本地服务支持 `X-Owner-Id: <用户标识>` 请求头（仅字母数字与 `-_.`，1~64 字符）——不同标识映射**相互独立**的演示工作区（输入/候选/计算/快照互不可见）。**这不是登录体系，也不是安全隔离**：`X-Owner-Id` 由客户端自报、可被任意冒用（`/api/state` 仅凭该头即可读取对应工作区；`/api/session` 据此直接发放写令牌）——本地单用户演示下这只是**键空间分区**。生产化契约已写入文档：owner 必须来自宿主系统验证后的用户上下文，不得信任客户端自报头。

| 核对项 | 预期行为 | 验证方式 |
|---|---|---|
| 未携带 X-Owner-Id | 使用默认工作区（单用户演示模式，兼容本文全部走查步骤） | ✅ 默认流程正常 |
| owner-A 保存输入/快照后，owner-B 查询 | B 看不到 A 的任何数据（state 为空白初始态） | ✅ 接口测试 `test_preinitiation_partition.py`（服务层 + HTTP 层共 10 项） |
| owner-B 尝试修改/确认 A 的快照 | 拒绝（资源不存在于 B 的命名空间） | ✅ 同上 |
| 非法 owner 标识（超长/非法字符/过多不同标识） | 请求被拒（invalid_owner_id / too_many_owners） | ✅ 同上 |
| **冒用测试**（S3 验收轮新增）：任取 owner-A 的标识头即可读取/写入其全部数据 | 如实记录：**可冒用**（客户端自报无认证）——已按"数据分区（非安全隔离）"修正全部文档表述，生产适配契约见上 | ✅ `TestHttpImpersonation`（HTTP 层实测冒用成功，作为风险证据保留） |

## 6. 已知限制与未验证项（如实声明）

1. **非生产**：`http.server` 与内存 Repository 仅供本地演示，**不可用于生产**。
2. **无持久化 / 无并发保障**：重启即丢失全部数据。
3. **固定测试结果**：演示测算使用 `TestOnlyProvider` 固定利润率（默认 18%），**不随输入计算真实利润**；真实计算入口恒 `blocked`（公式未过 (c) 级验证：D1/D2/D5/Q1/Q3/B1）。
4. **0% 毛利采购价上限未启用**（Q3 + D5 未决），页面不展示虚构数值。
5. **不调用** OP / 1688 / 公司生产接口。
6. **未决事项照实显示**：审批顺序、宿主系统、确认角色（Q5/Q8）等一律标为「待确认」，本演示**不自行定案**。
7. **无 E2E 自动化**：仅有 HTTP 接口层自动化测试 + 本地浏览器手工走查，**不宣称端到端自动化通过**。
