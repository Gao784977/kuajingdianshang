# 02 · 一期范围与流程（MVP Scope & Flow）

> 前置：01-evidence-and-reuse.md（能力核查与阻塞项）
> 原则：不是重写旧项目，不是新建选品平台；一切已存在的环节优先复用公司现有系统。
> **S0 修订（2026-10-15 评审整改）**：测算/0%毛利环节改为 blocked 状态表述；新增 §2.3 实体区分与流程冲突清单（Q8）；确认双轨制（demo/real）；快照确认倾向实现为提交前校验；四元组约束表述按保证边界修正。修订溯源见 05 文档。
> **S2 修订（2026-10-15 本轮）**：① §2.3/§4 引入对接状态三态（页面可见 ≠ 接口契约已知 ≠ 接口已对接，定义见 01 §2.8），明确现有审批中心仅完成页面级观察；② §6 demo/real 隔离声明补充"本轮实现已强制执行"条款——演示参数结果不能进行正式业务确认、审批或产品转换，该限制不只在文档，也在服务层门禁与导出契约中执行（证据见 07 交付报告）。

## 1. 一期目标（一句话）

在**现有开发任务**内，把「补输入 → 测算（真实入口 blocked，demo 验证编排）→ 采购价约束 → 1688候选 → 选offer/SKU → 复算 → 决策快照 → 确认（模拟/正式双轨）→ 接入现有待开发产品/立项流程」串成一条**可追溯、可失效感知**的最小闭环，消除预立项阶段在多系统间的重复录入与口径不一致。

## 2. 一期范围

### 2.1 做

| 环节 | 说明 | 依托 |
|---|---|---|
| 预立项工作区 | 在开发任务详情内新增一个只读+表单区块（具体宿主系统见 Q4） | 新增 |
| 最小输入集 | 参考ASIN、市场（一期仅美区）、平台（一期仅 Amazon SC）、售价 或 目标利润率（互斥录入约束，**不构成完整性判据**，完整性按 03 §2.1 逐项判定）、活动营销费占比、目标采购量（None=未知）、汇率、首轮估算采购价 | 新增，字段对齐 OP 计算器 |
| 测算 | 真实入口 blocked（D1/D2/D5/Q1 未决）→ 返回原因不输出数值；demo 模式用 test_only 提供者验证编排 | 新增（blocked 状态实现，S1 已落地） |
| 溯源价格上限 | 仅用目标采购价区间；0%毛利推算采购价 blocked（Q3+D5），一期不产出 | blocked 项明示 |
| 1688候选 | 优先接 OpenAPI（B2 阻塞时降级：手工录入候选，来源 manual、准入状态 unknown、报价溯源字段必填） | 新增，设计借鉴 1688 方案 |
| offer/SKU 选择 | 候选列表勾选；有效采购价仅取 SKU 级价格（搜索报价仅展示） | 新增 |
| 有效采购价复算 | 用所选 SKU 对应采购量档位价格重算 | 新增 |
| 决策快照 | 不可变内容 + 可追加事件（03 §4.6） | 新增 |
| 人工确认 | **双轨**：demo=模拟确认（demo_confirmed 事件，永不升级）/ real=正式确认（七项门禁，03 §6）；real 确认与现有审批的关系**待 Q5/Q8 裁决** | 复用品牌中心审批（关系待确认） |
| 转待开发产品 | real 确认后生成/更新待开发 SPU/SKU；**生成时点与审批先后存在未决冲突（§2.3/Q8）** | 复用（接口待 B4，时点待 Q8） |

### 2.2 非目标（一期不做）

- ❌ 新建登录/权限/审批系统（复用现有 SSO 与审批中心）
- ❌ 多 Agent 编排、自创综合评分
- ❌ 自创利润公式；反推类公式（反推售价/0%毛利采购价）在 D5/Q3 裁决前不作为正式能力
- ❌ 多市场/多平台分支（欧区 VAT、日本消费税、VC、Net PPM 等列入二期）
- ❌ 敏感性分析/三情景
- ❌ Excel 批量导入、卖家精灵管道、URL 抓取
- ❌ 数据库迁移、队列、部署平台升级（**当前阶段限制**——S1 用进程内内存验证；未来生产存储需独立方案报批，见 03 §7）
- ❌ 供应商智能匹配
- ❌ 溯源自动重试、定时刷新

### 2.3 业务实体区分与流程冲突清单（S0 新增，未确认前不固化）

**实体区分**：
| 实体 | 观察来源 | 说明 |
|---|---|---|
| 项目 | 品牌中心 project-management（预立项/立项阶段挂于项目） | 表头含项目编号/品线/状态（预立项待审核/待调研） |
| 开发任务 | 1688 原型 DT 编号实体 | **与"项目"的挂载关系未确认** |
| 参考 ASIN | 1688 原型任务详情模块 | 页面核查中未在品牌中心列表直接出现 |
| 待开发产品 | 1688 原型（SPU/SKU + 备选供应商） | 对应审批中心"SPU待审" |
| 预立项审批 | 审批中心"预立项待审"Tab | 入口存在，**节点关系未确认** |
| 立项审批 | 审批中心"立项待审"/"SPU待审"Tab | 同上 |

**观察证据的边界（S2 强化）**：页面观察到审批 Tab 仅证明**入口存在（对接三态之①"页面可见"）**，不能证明其与本项目节点的先后/父子关系一致。**对现有审批中心的核查目前仅完成页面级观察；接口契约（②）与接口权限（③）均待核实（B4）——在②达成前，任何"接入审批"的表述均不成立。**三态定义见 01 §2.8。

**未决冲突（Q8，未确认前流程不固化）**：
1. **产品生成时点**：本方案 v1 假设"快照 real 确认 → 转待开发产品 → 提交预立项审批"；但审批中心同时存在"预立项待审"与"SPU待审"，可能意味着现行流程是"预立项审批通过 → 才建产品（SPU 再审）"——两种顺序互斥。
2. **开发任务 vs 项目**：1688 原型以"开发任务"为主实体，品牌中心以"项目"为主实体，挂载关系未确认。
3. **快照确认与审批的关系**：独立确认节点 or 现有提交动作前的校验门禁（倾向后者，待 Q5）。

## 3. 现状流程 vs 目标流程

### 现状（推断自原型方案 §2 与页面核查，含人工环节）

```
开发任务(品牌中心) → 人工去 OP 计算器测算(手工抄参数) → 人工去 1688/寻源通找货
→ 人工比对采购价 vs 测算 → 人工回品牌中心建待开发产品 → 提交审批
   （各环节数据不通，重复录入，口径漂移，无可追溯快照）
```

### 目标（一期）

```
[现有]开发任务/参考ASIN
  → ①补齐最小输入(input_version 管理)
  → ②测算：真实入口 blocked(D1/D2/D5/Q1)；demo 模式 test_only → 利润率(可为负)/不可计算(原因)
  → ③溯源价格上限 = 目标采购价区间（0%毛利推算 blocked·Q3）
  → ④1688候选(批次) [API 或 手工降级(manual, 准入=unknown)]
  → ⑤人工选 offer/SKU（有效采购价=SKU级价格，搜索报价仅展示）
  → ⑥有效采购价复算
  → ⑦决策快照(不可变内容+事件)
  → ⑧确认：demo=模拟确认 / real=正式确认(七项门禁，03 §6)
  → [现有]审批/待开发产品流程（顺序待 Q8 裁决）
```

①→⑦ 中任何计算相关输入修改：相关结果按 03 §5 失效矩阵标过期，不静默沿用。

## 5. 状态机与门禁（对象分离，字段定义见 03 §4）

### 5.1 测算状态 `calc_status`
`input_incomplete → ok | not_computable | blocked`；引用的 input_version/params_version 落后于当前 → 派生 `stale`。

### 5.2 溯源批次状态 `sourcing_status`
`pending → running → succeeded_with_results | succeeded_zero | partial_failed | failed`；`not_auto_sourced`（价格约束不可用时）。批次不可变；重新溯源=新批次号。

### 5.3 候选状态 `candidate_status`
`pending_selection → selected → converted`；`pending_selection → discarded`。

### 5.4 快照状态（由事件序列派生，03 §4.6）
`pending_confirm → demo_confirmed(模拟确认) | real_confirmed | rejected`
- demo 与 real 是**不同事件、不同状态**，模拟确认永不升级为正式确认。
- 输入变更使旧快照"不再代表当前版本"（派生标志 is_current=False），**内容与事件历史不变**。

### 5.5 门禁规则

| 动作 | 阻止条件 |
|---|---|
| 生成快照 | calc_status ≠ ok；或候选未 selected；或所选 SKU 无 SKU 级有效采购价（搜索报价不得替代） |
| 快照 **real** 确认 | 七项门禁（03 §6）：公式 verified / 参数完整且当前版 / 输入完整 / 有效采购价 / qty_check=passed / 未过期 / 未被拒绝 |
| 快照 **demo** 确认 | 仅要求未过期（模拟确认也要反映真实流程的时效语义） |
| 转待开发产品 | 快照无 real_confirmed 事件；四元组(任务,ASIN,offerId,skuId)已存在（S1 为进程内检查，生产级约束待存储方案） |
| 提交审批（复用现有校验） | 沿用品牌中心现有规则；顺序待 Q8 |

### 5.6 失效与防重复（摘要，规则全文见 03 §5）

- 计算相关输入修改 → `input_version`+1 → 引用旧版本的计算结果/快照 is_current=False；**已确认快照不删除不改写**（历史审批以提交时的 snapshot_id 为准）。
- 重新溯源 → 新批次；converted 候选跨批次保留标记；selected 候选保留但标注"基于旧批次"。
- 重复请求 → 幂等：确认不重复产生事件；转待开发产品按四元组防重（保证边界见 03 §4.7）。

## 6. 范围外风险声明与 demo/real 隔离

- **demo/real 双轨隔离（03 §6）**：test_only 提供者、样例参数、手工候选属 demo 域——只能"模拟确认"，导出带演示水印与机器可读 `{"demo": true}` 字段；真实确认/真实产品生成/正式审批提交在公式解封前一律 blocked。
- B1（参数表）未解时，任何测算输出 `sample_parameters=true` 显式标注，**禁止进入真实立项决策**。
- B2（1688 API）未解时，候选为手工录入（来源 manual、准入状态 unknown），快照中如实标注。
- **演示结果的硬边界（S2 强调：不只在文档，实现同样执行）**：演示参数生成的结果**不能进行正式业务确认、审批或产品转换**。本轮实现中该限制由以下机制强制执行，而非仅靠文档声明：
  - 正式确认七项门禁中第①项（公式 verification=verified）在公式解封前恒不通过，real 确认必拒并返回原因清单；
  - 导出契约携带 `approved_for_decision: false`（恒 False，本轮不开放"确认并转产品"）与强制水印「待核验预览单——非正式测算，禁止用于审批或采购决策」；
  - 浏览器/请求参数无法将 demo 结果提升为 real——mode 由服务端判定，demo 计算结果的 verification 恒为 test_only，real 门禁据此拒绝；
  - 详见 07 交付报告 §5（已实现/契约/演示边界）与对应测试（test_preinitiation_snapshot_confirm.py / test_preinitiation_versions.py）。
